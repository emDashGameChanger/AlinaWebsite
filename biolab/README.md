# biolab

Molecular docking tooling and a worked example for the BioMedBound project.

## What's here

- `config.txt` — AutoDock-Vina-GPU config for the example docking run
- `receptor.pdbqt`, `ligand.pdbqt`, `ligand.sdf` — prepared example receptor/ligand
- `ligand_out.pdbqt`, `output.pdbqt`, `log.txt` — output/log from the example run
- `3I3R.pdb`, `3I3R_out/` — fpocket pocket-detection output for receptor 3I3R (59 candidate pockets)
- `environment.yml` — conda env spec (`pymol-open-source`, `openbabel`, `rdkit`,
  `meeko`, and friends — see [Drug library](#drug-library) below)
- `setup.sh` — reproducible build script for fpocket + AutoDock-Vina-GPU-2.1
- `scripts/` — the drug-library fetch/prep/batch-dock pipeline (see below)
- `data/drug_library.csv` — the FDA-approved drug library (SMILES + metadata)
- `ligands/` — one prepared PDBQT per drug (not committed — regenerable)
- `runs/` — per-screen config/log/results (not committed — regenerable)

Not committed to git (machine/GPU-specific, regenerated by `setup.sh`):
`AutoDock-Vina-GPU-2-1` (compiled binary), `OpenCL` (symlink), `Kernel1_Opt.bin` /
`Kernel2_Opt.bin` (OpenCL kernel caches), `vendor/` (cloned upstream source).

## Setup

```bash
bash setup.sh
```

This installs apt prerequisites (build-essential, cmake, boost, CUDA toolkit),
builds fpocket, creates the `biolab` conda env, and builds AutoDock-Vina-GPU-2.1
from source — following the same steps documented in the website's
[Software Install tutorial](../molecularDocking/softwareInstall.html).

Already built on this machine? `setup.sh` is idempotent — it skips steps that
are already done. Use `bash setup.sh --force` to rebuild from scratch.

## Running the example

```bash
conda activate biolab
./AutoDock-Vina-GPU-2-1 --config config.txt
```

For the narrated walkthrough of what this example does and why, see the
tutorials on the website: [Hello Tools Part 1](../molecularDocking/Hello1.html)
and [Hello Tools Part 2](../molecularDocking/Hello2.html) (fpocket-guided
targeted docking).

## Drug library

The whole point of this project is screening FDA-approved drugs against a
disease target, so `biolab/` includes a pipeline to build a ready-to-dock
library of them:

```bash
conda activate biolab
python3 scripts/fetch_drug_library.py        # DrugCentral -> data/drug_library.csv
python3 scripts/prepare_ligand_library.py    # SMILES -> ligands/<id>.pdbqt
python3 scripts/batch_dock.py --run-name <name> [--limit N]
```

- **`fetch_drug_library.py`** downloads DrugCentral's "FDA Approved Drugs"
  list and structures file (open access, no login, CC BY-SA 4.0 — cite
  DrugCentral if used in any published results) and joins them into
  `data/drug_library.csv`: one row per approved drug with a SMILES string,
  source, version, and the date it was pulled. Currently ~1,859 drugs (some
  approved entries, mostly biologics/peptides/inorganics, have no simple
  small-molecule SMILES and are skipped).
- **`prepare_ligand_library.py`** converts each SMILES into a docking-ready
  PDBQT: RDKit embeds a 3D conformer (ETKDGv3, fixed random seed for
  reproducibility) and MMFF94-optimizes it, then
  [Meeko](https://meeko.readthedocs.io/) (the Forli Lab's official
  AutoDock-Vina/Vina-GPU ligand writer) exports the PDBQT. Macrocycles are
  kept rigid (`rigid_macrocycles=True`) because Vina-GPU-2.1's atom-type
  table doesn't support Meeko's macrocycle "glue" pseudo-atoms. Resumable —
  skips ligands already prepared unless `--force`; failures are logged to
  `data/ligand_prep_failures.csv` rather than aborting the batch.
- **`batch_dock.py`** runs AutoDock-Vina-GPU-2.1's native
  `--ligand_directory` / `--output_directory` virtual-screening mode against
  a chosen receptor (defaults to `receptor.pdbqt` + the box in `config.txt`,
  i.e. the 3I3R demo — pass `--receptor`/`--config` to point at a real
  target once one is chosen). It pre-filters ligands over Vina-GPU-2.1's
  hard 130-atom limit (logged to `runs/<name>/skipped_too_large.csv` rather
  than silently failing mid-run), then writes a ranked
  `runs/<name>/results.csv` (drug, best predicted affinity in kcal/mol)
  parsed from Vina's own `REMARK VINA RESULT` lines. Use `--limit N` to
  smoke-test on a small subset before committing to a full-library run.

See the `docking-run` and `target-research` Claude Code skills
(`~/.claude/skills/`) for the conventions around actually using this for a
real screening campaign once a disease target is picked.
